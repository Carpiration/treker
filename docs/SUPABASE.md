# Подключение синхронизации (Supabase)

Без этих шагов приложение работает локально: данные только в том браузере, где их ввели.
С Supabase задачи общие для всех устройств и обновляются в реальном времени. Бесплатного тарифа хватает.

## 1. Проект
1. Зарегистрируйтесь на https://supabase.com и нажмите **New project**.
2. Имя — любое (например, `treker`), регион — ближайший (Frankfurt / `eu-central-1`).
   Пароль базы данных сохраните у себя — для приложения он не нужен, никому его не пересылайте.

## 2. Отключить подтверждение e-mail
Вход — по номеру телефона и PIN, без SMS. Внутри Supabase номер хранится как служебный адрес
`79991234567@treker.local`, писем на него не отправляется.

**Authentication → Sign In / Providers → Email → выключить «Confirm email» → Save.**

Регистрацию («Allow new users to sign up») оставьте включённой: через неё люди регистрируются сами.

## 3. Таблицы и правила доступа
**SQL Editor → New query →** вставьте целиком файл [`supabase/schema.sql`](../supabase/schema.sql) → **Run**.
Должно появиться `Success. No rows returned`. Повторный запуск безопасен.

## 4. Ключи
**Project Settings → API Keys** (или кнопка **Connect**):
- **Project URL** (`https://abcdefgh.supabase.co`) и **Publishable key** (`sb_publishable_…`) — публичные,
  их вписывают в `config.js` (можно прислать в чат);
- **Secret key** (`sb_secret_…`) — полный доступ к базе. В чат и в файлы сайта не отправлять.
  Чтобы Claude мог смотреть и вносить задачи, скопируйте `.env.example` в `.env` в папке проекта и вставьте его туда.
  Файл `.env` остаётся только на этом компьютере и не попадает в GitHub.

## 5. Регистрация
Откройте сайт → **Регистрация**: имя, номер телефона, PIN из 6 цифр.
- Первый зарегистрированный становится **администратором** и сразу входит.
- Остальные после регистрации видят «Заявка отправлена». У администратора на шестерёнке появляется точка,
  в **Настройки → Профили** — заявка с кнопкой **Одобрить**. До одобрения человек не видит задач.
- Администратор может и сам добавить сотрудника (номер + PIN) — тогда одобрение не нужно.

Если на устройстве остались задачи из локального режима или из Android-приложения 1.0,
в настройках администратора появится кнопка **«Перенести задачи»**.

## Работа с задачами из командной строки
После шага с `.env`:
```
python tools/db.py users
python tools/db.py list --done
python tools/db.py add "Позвонить поставщику" --to "Иван" --desc "Уточнить сроки"
python tools/db.py set 3f2a1c9b --status done
```

## Если что-то пошло не так
- **«Включено подтверждение e-mail»** — выполните шаг 2, затем в SQL Editor:
  `update auth.users set email_confirmed_at = now() where email_confirmed_at is null;`
- **«Сервер не принял номер»** — поменяйте `loginDomain` в `config.js` (например, на `treker.example`),
  только пока не зарегистрирован ни один профиль.
- **Забыт PIN** — администратор задаёт новый в **Настройки → Профили**. Если забыл сам администратор —
  в SQL Editor (номер — только цифры):
  `update auth.users set encrypted_password = extensions.crypt('123456', extensions.gen_salt('bf')) where email = '79991234567@treker.local';`
